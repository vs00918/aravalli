## 2. The Permanent Operating Workflow

### A. The Ingestion Command
To process any new current-affairs PDF batch:
```bash
npm run ingest -- data/incoming-feed.json
```
*(or point to any JSON feed extracted from a new PDF)*.

### B. Input Format
Standard JSON array of items conforming to:
```json
[
  {
    "id": "BATCH-ITEM-01",
    "headline": "RBI Issues Guidelines on...",
    "bodyText": "Key facts, amounts, and dates...",
    "sourceName": "CGB_MENTORS",
    "batchName": "CGB_Mentors_October_2026_Weekly_1.pdf",
    "publishedDate": "2026-10-05",
    "priorityHint": "P1",
    "categoryHint": "BANKING_REGULATION"
  }
]
```

### C. Output Locations
1. **Master Canonical Registry**: `data/banking-ca-registry.json` (Automatically compiled, deduplicated, enriched, and synced).
2. **Persistent Layer-B Registry**: `data/verification-registry.json` (Reusable evidence hashes).
3. **Exception Review Queue**: `data/review-queue.json` (Populated **only** when human intervention is needed).

---

## 3. Human Review Invariant (Exception-Only)

Operators **never** need to author topic mappings or audit notes manually. Human review is triggered **only** for:
1. **`CONFLICT_DETECTED`**: Two sources reporting contradictory numbers (e.g. 6.25% vs 6.50% repo rate).
2. **`AMBIGUOUS_ENTITY_MATCH`**: Unclear whether a new scheme is a brand-new entity or a revision of an existing scheme.
3. **`UNVERIFIED_PRIMARY_SOURCE`**: High-priority claim where official source endpoint is dead or blocked.
