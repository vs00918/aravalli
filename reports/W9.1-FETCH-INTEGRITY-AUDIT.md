## 1. Forensic Dissection of the Hash-Collision Anomaly

In the W9 pilot, the audit reported:
- **MPC Artifact**: SHA-256 `a5231e5d0f5ef1db0135c2846502da6d57e55acbe3da07826b8c02dc36a68822`, `177,721 bytes`
- **623rd Central Board Artifact**: SHA-256 `16c878a6972d323c7399c4ac1bb41812b0ddcc9df0eea1d500b747a3af79f578`, `177,721 bytes`

### Root Cause Analysis
The script `scratch/execute_w9_pilot.js` requested `https://www.rbi.org.in` (the root domain) rather than fetching and verifying the specific document payloads. Because both topics fetched the generic RBI root homepage:
1. Both returned the **exact same homepage HTML payload** (`177,721 bytes`).
2. Both generated the **exact same SHA-256 hash**.
3. **Neither payload actually contained the specific topic resolution text** (`MPC-62`, `5.25%`, or `₹2,86,588.46 crore`).

The pilot verification engine accepted generic homepage HTML and extracted claims from memory rather than proving the evidence existed inside the retrieved payload.

## 3. Code Inspection of `lib/banking-ca/verification-fetcher.ts`

Review of `lib/banking-ca/verification-fetcher.ts`:
- **Redirects**: Properly follows 301/302 redirects.
- **Vulnerability**: The fetcher accepts any 200 OK HTML payload without verifying whether the document title/body matches the requested document identifier.
- **Failure Mode**: When a government server returns a generic landing page or redirect for a specific query parameter, the fetcher treated the generic landing page as the official document.
